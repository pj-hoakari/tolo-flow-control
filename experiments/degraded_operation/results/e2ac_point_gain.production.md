# E2(a)(c): 観測点ごとのゲインが決定に与える影響と、推定ゲインによる補正

設定: tolo-observation の defaultFlowConfig。ただし通行制限のスイッチとしきい値はシナリオの値を使う（本番では通行制限は無効）。

## 設定

対象は E1 と同じ 11 シナリオ（履歴あり）。シードは各シナリオ 50。観測点はエッジのカメラで、そのエッジの flow_rate・flow_samples・directional_flow_samples・observed_count・stagnation・stagnation_samples・p90_stagnation・baseline_stagnation を同じ g_e 倍する。混在ノードの占有センサは独自の g_v で occupancy と occupancy_delta を倍する。g は [0.6, 1.5] の対数一様。capacity_hint・danger_capacity・danger_flow_capacity は運用者が真の単位で設定する値なので動かさない。比較の基準は g=1 の実行の署名である。

決定種別は verdict、triggered（発火エッジ・ノードの集合）、direction（KEEP 以外の方向提案）、boundary（境界制御）、restriction（通行制限の有無・種類・理由）、detour（採用迂回パス）、emphasis（重要度の順位。1e-6 で同着をまとめる）。core は emphasis を除く 6 種のどれかが変わった割合。制限値 limit_value は連続量なので一致判定に入れず、g=1 との相対差の中央値 / p90 を別に示す。

## E2(c): 補正の各条件と決定の食い違い

- none: 補正なし（E2(a) と同じ）。
- oracle_edges_abs: エッジのゲインを完全に補正する。占有センサの g_v は残る。相対推定でどこまで下がるかの床。
- oracle_edges_rel: エッジを参照点に対する比で完全に補正する。参照点自身のゲイン g_ref が全エッジに共通の倍率として残る。
- oracle_all_rel: 占有センサも含めて全点に共通の倍率 g_ref だけが残る。E1 の obs_only を g_ref ∈ [0.6, 1.5] で試すのと同じ。
- inject:<モデル>:<窓数>: 参照点のゲインは既知とし、他のエッジの相対ゲインに E2(b) の推定誤差を載せる。誤差は E2(b) の grid(3,3)・bidir・Δt=30 秒・流量 20・iv 推定の結果から点ごとに再標本化する。推定が出なかった点（h ≤ 0 など）は補正しない。
- density:<b>: g0 は完全に補正するが、ゲインが密度で g0·(1 − b·ρ) に下がる。ρ はスナップショットの観測流量/60。一定の ĝ は較正期間の平均密度（スナップショットの 0.5 倍と仮定）で当てはまったものとする。
- loop:<窓数>: シナリオ自身のグラフとカメラ配置で多窓の系列を合成し（thinned モデル、流量 20、iv）、推定できた点だけを 1/ĝ で補正する。参照点は未知のままなので g_ref が残る。

## この数字が別のものを測っている可能性

- 時間予算による打ち切り: 全実行で greedy_truncated が偽、solver_status が TIMEOUT でないことを assert した（_common.evaluate）。
- 変換が効いていない: 全実行で、変換前後の浮動小数の葉の比が点ごとの係数に一致することを assert した。
- emphasis の揺れ: E1 の退化検査で、station-transfer-peak の重要度順位は epsilon_0 を 0 倍・2 倍しただけで入れ替わる。emphasis の食い違いには、ゲインの効果ではなく LP の代替最適解の揺れが混ざる。core と分けて示したのはこのためである。
- 基準の選び方: g=1 を「正しい決定」とみなしている。g=1 のシナリオの決定そのものが境目に乗っていれば、小さなゲインでも食い違いが出る。シナリオ間の最小/中央/最大を並べたのは、少数のシナリオが全体の割合を決めていないかを見るためである。
- 短い窓の inject が none より悪い理由: 中央値 300% を超える誤差の推定値を、もっともらしさの検査なしにそのまま当てている。ĝ が一定の範囲を外れたら捨てる検査を入れれば、短い窓の条件は none に近づくはずで、none を下回る（良くなる）ことは期待できない。「補正しないより悪い」はこの素通しの条件での結果である。
- 注入誤差の出どころ: inject の誤差は grid(3,3) という好条件のグラフで推定したものを、別のグラフのシナリオへ再標本化している。誤差の点間相関や、流量水準の違いは持ち込んでいない。
- 密度の仮定: density の ρ はスナップショットの流量を公称容量 60 人/分で割った値で、較正期間の平均密度をその半分と置いた。どちらも実測していない。
- capacity を据え置く選択: 共通倍率が残る条件（oracle_edges_rel、oracle_all_rel、loop）の食い違いは、delta_min と capacity_hint・danger_capacity・danger_flow_capacity が真の単位の絶対値であることから来る（E1 の obs_only と同じ機構）。
